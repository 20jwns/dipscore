# AI 모의투자 앱 최종 기획서

> 작성 기준일: 2026-08-23
> 목적: 재테크 목적의 AI 모의투자 앱 — 개발 경험이 아니라 실제 흑자를 낼 수 있는 투자 로직 구현이 핵심 목표

---

## 1. 전체 개요

### 1-1. 앱 목적 및 핵심 흐름
1. 토스증권 API를 기본으로 하되, 필요한 데이터는 다른 API도 함께 활용해 최신 종목 데이터 수집
2. 종목 데이터 + 투자 성향/전략을 취합해 "매수 매력도 지수" 공식 설계
3. 그 공식으로 모의투자(가상자산, 실제 투자 가능한 현금 규모만큼 설정) 백테스트 실행
4. 적자 나면 공식 계속 수정, 흑자 전환되고 공식이 안정화되면 실제 AI 투자 앱으로 전환
5. 앱 전환 이후에도 모의투자 + AI 모의투자 기능은 그대로 유지

### 1-2. 3대 핵심 기능 및 개발 단계
| 기능 | 설명 | 거래 API 사용 여부 |
|---|---|---|
| ① 직접 모의투자 | 사용자가 직접 매매 판단, 가상 자산으로 시뮬레이션 | 시세/계좌 조회만 (주문 API 미사용) |
| ② AI 모의투자 | AI가 매수/매도 신호 생성, 가상 체결로 시뮬레이션 | 시세/계좌 조회만 (주문 API 미사용) |
| ③ AI 실전투자 | AI 신호로 실제 계좌 매매 실행 | 실제 토스 주문 API 사용 |

**개발 단계별 출시 계획**
- 1차: 직접 모의투자 + AI 모의투자 2개 기능만 먼저 개발
- AI 모의투자가 백테스트+실운영 병행으로 어느 정도 검증되면 → AI 실전투자 기능 추가 개발
- AI 실전투자 전환 후에도 최소 3개월간 실운영하며 검증하는 기간을 가짐

### 1-3. 자산군 범위 (확정)
국내 주식, 미국 주식, ETF (코인 등 제외)

## 2. 법적/규제 이슈 검토

### 2-1. 본인 전용 사용 (현재 계획 범위)
- 본인 계좌·본인 자금으로 본인만 사용 시 자본시장법상 인허가/신고 이슈 없음
- 챙겨야 할 실무 사항:
  - 증권사 API 이용약관 준수 (본인 명의 계좌·목적으로만 사용, 타인 계좌 대신 운용 금지, API 재배포/재판매 금지)
  - 미국주식 양도소득세 신고 의무 (연 250만원 초과분 22%)
  - 자동매매 오류에 대한 책임은 사용자 본인에게 있음 (증권사 면책 조항)

### 2-2. 향후 서비스화 시 (다른 사람도 사용하는 경우) — 참고용
- 불특정 다수 대상 "신호 발생 → 자동 매매 실행" 구조는 유사투자자문업 신고만으로는 불가 (금융위 유권해석상 유사투자자문업자에게 AI 자동매매 미허용)
- 사용자 성향 기반 AI 자동 판단·매매 구조는 투자일임업에 해당할 가능성 높음 (등록 요건: 자기자본 1억원 이상, 투자권유자문인력/투자운용인력 확보)
- "사용자가 조건을 다 설정하고 시스템은 실행만" 하는 구조로 설계하면 규제 문턱을 낮출 여지 있음 (단, 실제 설계·약관 기준 개별 판단 필요)
- 이 시나리오는 현재 계획 범위 밖이며, 실제 서비스화 검토 시점에 법률 자문 필요

## 4. 매수 매력도 지수 설계

### 4-1. 공식 구조
```
매력도 지수 = 기본점수(펀더멘털+수급+거시) × 이벤트 조정계수
```

### 4-2. 기본점수 구성 항목
- **종목 자체 펀더멘털**: 밸류에이션(PER/PBR/PSR/PEG/EV-EBITDA), 재무건전성(부채비율/유동비율/영업현금흐름/이자보상배율), 수익성·성장성(매출성장률/영업이익률/ROE), 사업 경쟁력, 수급(대주주 지분율/유증·CB 이력/외국인·기관 순매수), 전망
- **거시/기술적 변수**: 거시경제(기준금리/환율/CPI/유가/GDP/산업생산지수), 산업사이클, 시장심리(공매도잔고/신용융자잔고/VIX), 글로벌연동

### 4-3. 정규화 방식 (확정)
| 지표 유형 | 정규화 방식 | 이유 |
|---|---|---|
| 밸류에이션/재무/수익성 등 | **업종 percentile** | 업종별 정상 범위가 크게 다름, 국내+미국+ETF 혼합 비교에 유리, 이상치에 강함 |
| 거시경제 변수 | **Z-score** | 업종 구분이 무의미한 값 |
| ETF | 기초자산 카테고리별 별도 percentile 그룹 | 개별 종목과 성격이 다름 |

### 4-4. 가중치 산정 방법 (확정) — 4단계 방법론
1. 전문가 초안 (주관적 초기 가중치)
2. 베이지안 최적화 (그리드서치 대신, 훈련 데이터 기반 탐색)
3. Walk-forward validation (국면별 안정성 확인)
4. 요인 제거 테스트 (각 요인의 실제 기여도 검증)

- 1차 구현은 핵심 요인 5~7개로 시작
- 가중치는 분기/반기 단위로 재검증

### 4-5. 이벤트 조정계수 세부 로직 (확정)

**기본 구조**
```
조정계수 = 카테고리별 기본조정폭 × 감성점수 강도 (카테고리 상한선으로 안전장치)
```

**감성분석**: 직접 파인튜닝 방식 채택

**다중 뉴스 처리**: 부정 이벤트 우선 반영 + 긍정 이벤트는 보조적으로 가산 (리스크 관리 우선 철학)

**신뢰도 가중**
| 출처 유형 | 반영 방식 |
|---|---|
| 공식 공시/주요 언론사 1보 | 정식 반영 (가중치 0.7 이상) |
| 일반 언론사 후속보도 | 낮은 가중치 |
| 커뮤니티/블로그/SNS | 완전 배제 |

**감쇠(decay)**: 이벤트 성격별 차등 적용
- 단발성 이벤트 (실적발표, 계약체결 등): 5~7일에 걸쳐 감쇠
- 진행형 리스크 (소송, 규제 리스크 등): 느린 감쇠 또는 유지
- 정책/구조적 이벤트 (관세, 산업규제): 감쇠 없이 갱신 시까지 유지

**파인튜닝 라벨링 기준**: 벤치마크 대비 초과수익률(실제 주가 변동 결과) 기준 메인 + 초기 데이터 부족 구간은 사람 라벨링 소량 병행 (하이브리드 부트스트래핑)

**잔여 항목** (개발 착수 시점 결정): 카테고리별 정확한 숫자값, 콜드스타트 데이터 확보 전략

## 5. 저점 진입 스코어 설계

### 5-1. 공식 구조
```
저점 진입 스코어 = (반등신호×가중치A) + (기술적지표×가중치B) + (매력도지수×가중치C)
```

### 5-2. 세부 신호 정의 (확정)
- **반등신호**: 절대% 대신 ATR 대비 상대 구간으로 정규화 (0.5~1.5×ATR 구간에서 최고점, 너무 낮거나 3배 초과 시 낮은 점수)
- **기술적지표**: RSI(14일 기준, 과매도 30 이하 후 상향돌파) + 볼린저밴드(20일 하단선 터치 후 복귀) 조합으로 1차 구현. 이동평균 이격도는 상관관계가 높아 2차 확장 후보로 보류
- **매력도지수**: 1차 필터(기본점수 ≥60점 통과 종목만 대상) + 2차 가중요소(C) 이중 역할

### 5-3. 가중치 A/B/C
- 초안: A(반등신호) 0.3 / B(기술지표) 0.3 / C(매력도지수) 0.4
- 기본점수 가중치와 동일한 4단계 방법론(전문가초안→베이지안최적화→walk-forward검증→요인제거테스트)으로 확정
- 진입조건 임계값(스코어 ≥70)도 백테스트로 조정 예정

## 6. 리스크 관리 (3단 계층)

### 6-1. 1층 — 종목당 손절
- ATR 기반 변동성 손절: 손절가 = 매수가 - (ATR × 1~1.5배)
- 향후 트레일링 스탑 확장 고려 (스윙/장기 전략 도입 시)

### 6-2. 2층 — 종목당 사이징
- 변동성 기반 사이징: `매수 수량 = (계좌 전체 자산 × 리스크 허용 비율) / (매수가 - 손절가)`
- 성향별 상한 비중으로 캡 적용
- 켈리 기준은 백테스트 데이터 축적 후 참고용으로만 활용 (1/2~1/4 켈리로 보수적 적용)

### 6-3. 3층 — 포트폴리오 레벨
- 일일 손실 한도: 하루 누적 손실이 계좌의 -3% 초과 시 당일 신규 매수 중단
- 최대 동시보유 종목수 제한
- 섹터별 최대 비중 상한 (분산효과 확보)
- 연속손실 시 포지션 사이즈 자동 축소 (쿨다운)

## 7. 매매 실행 로직

### 7-1. 매수 신호 룰 (AND 조건)
```
IF 저점 진입 스코어 ≥ 70
AND 매력도 지수 기본점수 ≥ 60
AND 이벤트 조정계수가 음수 이벤트 없음 (조정계수 ≥ 0.9)
AND 보유 현금 > 최소 매수 단위
THEN 매수 신호 발생
```

### 7-2. 매도 신호 룰 (OR 조건)
```
IF (현재가-매수가)/매수가 ≥ 목표수익률 (익절)
OR (현재가-매수가)/매수가 ≤ -손절률 (손절)
OR 보유시간 ≥ 최대 보유시간 (장마감 15:20 강제청산)
THEN 매도 신호 발생
```

### 7-3. 기본값 (백테스트로 튜닝될 출발점, 데이트레이딩 전략 기준)
| 파라미터 | 초기값 | 베이지안 탐색 범위 |
|---|---|---|
| 목표수익률 | +2~3% (손익비 1.5~2배 유지) | 1.5~5% |
| 손절률 | ATR×1~1.5배 (대략 -1.5~3%) | ATR 배수 0.8~2배 |
| 상위 N개 종목 후보 | 10개 (안정형은 15개 고려) | 5~20개 |
| 최대 보유시간 | 장마감 15:20 강제청산 | - |

### 7-4. 종목당 투자 비중 배분 (성향별)
| 투자 성향 | 배분 방식 | 종목당 상한 | 최소 분산 종목수 |
|---|---|---|---|
| 안정형 | 균등 배분 + 고정 비중 상한제 | 5~8% | 8개 이상 |
| 중립형 | 균등 배분 + 고정 비중 상한제(완화) | 10~15% | 5개 이상 |
| 공격형 | 지수 점수 비례 배분 | 20~30% (상한 30~40%) | 3개 이상 |

### 7-5. 일일 배치 프로세스
1. 매일 장 시작 전: 전체 종목 대상 저점 진입 스코어 계산
2. 상위 N개 종목 선정
3. 투자 성향에 맞는 배분방식·상한 적용해 매수
4. 장중: 익절/손절/보유시간 조건 모니터링 → 조건 충족 시 즉시 매도
5. 장마감 15:20 시점: 미청산 포지션 전량 강제 매도
6. 수익 실현분: 원금 현금화 + 수익금만 다음날 재투자 풀에 편입

## 8. 성과 측정 및 벤치마크

### 8-1. 핵심 지표
- **초과수익률**: 내 전략 수익률 - 벤치마크 수익률
- **샤프비율**: (전략 평균수익률 - 무위험수익률) / 표준편차, 연율화 = 일간 샤프비율 × √252
- **MDD**: 최대낙폭, 드로다운 구간 음영 표시

### 8-2. 혼합 벤치마크 가중치 산정 방식 (확정)
- 기본 자산군 비중(코스피:S&P500:ETF 등)은 **고정 방식**으로 큰 틀을 잡고 분기/반기 단위로만 재검토
- **현금 비중은 실시간 반영**: 그날 전략이 실제 투자한 비중만큼만 벤치마크 수익률도 반영 (매수신호 없어 현금 보유 시 공정 비교 위함)
- 데이트레이딩 전략은 일간 벤치마크 vs 일간 전략 수익률 비교
- 장기보유 전략(추후 추가 시)은 누적수익률 곡선 비교
- 향후 사용자별 개인화 자산배분 목표 설정 기능 생기면 개인별 벤치마크 구성에도 반영 확장 고려

## 9. 몬테카를로 시뮬레이션

### 9-1. 초기조건 범위
- 시작시점을 국면별(상승/하락/횡보) 층화추출로 랜덤 샘플링 (1차)
- 슬리피지 노이즈(0.05~0.3% 랜덤) 추가 (2차)
- 종목풀 변동은 추후 확장

### 9-2. 병렬실행 개수
- 개발/검증 단계: 100~200회
- 전략 확정 후 정식 평가: 500~1000회

### 9-3. 결과집계 방식
- 평균뿐 아니라 중앙값/표준편차/5~95%ile 구간을 함께 확인
- 국면별(상승/하락/횡보)로 분리 집계
- 시각화: 히스토그램 + 스파게티 차트 + 요약박스

## 10. 백테스트 검증 방법론 (7단계 파이프라인)

1. **생존편향 방지**: Point-in-Time 유니버스 (그 시점 실제 존재했던 종목/지수구성으로 백테스트, 상장폐지는 -100% 반영)
2. **거래비용 반영**: 매 거래마다 증권거래세+매매수수료 차감, 슬리피지는 기본 고정모델(예: 매수매도 각 0.1%)로 상시 적용 (몬테카를로의 런별 슬리피지 노이즈와는 별개)
3. **데이터 3-way 분할**: train/validation/test, test는 마지막 딱 1회만 확인
4. **Walk-forward validation**: 시간축 롤링 반복검증 (국면별 층화와 연결)
5. **파라미터 개수 최소화**: 핵심 요인만, 데이터표본 대비 파라미터 비율 의식
6. **통계적 유의성 확인**: 랜덤 전략(무작위 매매) 대비 비교 (permutation test 개념)
7. **파라미터 민감도 분석**: 최적값 주변에서 성과가 완만하게 변하는지 확인해 과최적화 신호 감지

### 10-1. 데이터 파이프라인
- 갱신 주기: 주가/기술지표(실시간~5분), 재무제표(분기1회), 거시경제(일1회), 수급(일1회), 뉴스(실시간~수분)
- 과거 데이터: 최소 3~5년, 이상적으로 10년 이상
- 데이터 품질: 결측치는 fill-forward 대신 해당일 계산 대상 제외, 상장폐지 종목 반드시 포함, 이상치 자동 플래그, 수정주가 기준 사용

## 11. 사용자별 투자 전략/성향 설정 UI

### 11-1. 온보딩 설문 (5~7문항)
손실 감내 수준, 투자 목적, 경험 수준, 변동성 반응, 수익 목표 등 → 리스크 스코어(0~100) 자동 산출 → 성향 추천

### 11-2. 핵심 슬라이더 (초기화면 노출)
- 리스크 허용도 (0~100)
- 종목당 최대 투자 비중
- 투자 스타일 (데이트레이딩 / 추후 스윙·장기 확장)

### 11-3. 상세설정 (접힘, 숙련자용)
목표수익률, 손절률, 일일손실한도 등

### 11-4. 매핑 로직
- 리스크스코어 → 파라미터: 선형보간 (안정형 0~33 / 중립형 34~66 / 공격형 67~100 구간을 부드럽게 연결)
- 배분방식도 스코어에 따라 균등↔비례 점진적 블렌딩
- 슬라이더 조정은 언제든 가능하며 변경 시 신규 매매부터 반영 (기존 보유 포지션엔 소급 미적용)
- 재설문 버튼 별도 제공

## 12. UX 세부 구현

### 12-1. 1차 개발 화면
- **홈**: 요약카드(총손익/오늘신호/보유종목) + 오늘의 신호 리스트 + 보유종목 요약
- **종목 스코어 랭킹**: 섹터/자산군 필터 + 정렬 + 리스트
- **종목 상세(간이)**: 캔들차트 + 저점진입스코어 breakdown + 매력도지수 breakdown
- **매매 알림**: 푸시+인앱, 딥링크 연결
- **전략 설정**: 온보딩 설문 + 핵심 슬라이더 + 상세설정(접힘)

### 12-2. 2차 개발 화면
- **시뮬레이션 결과**: 요약박스 + 히스토그램 + 스파게티차트 + 국면별탭 + 벤치마크 비교 오버레이

### 12-3. 3차 (추후)
고도화 알림, 대시보드 커스터마이징 — 1~2차 구현 후 사용 패턴 보고 재우선순위화

### 12-4. 개발 원칙
- 컴포넌트는 Flutter 재사용 위젯 단위로 설계 (SignalCard/MetricBox/RiskSlider 등 화면 간 공용)
- 개발 워크플로우: 화면별 PNG 시안 → 구현 → 체크포인트 (Triplan과 동일 방식)
- 1차 우선순위는 직접모의투자+AI모의투자에 필요한 화면만 먼저, 시뮬레이션결과 화면은 시뮬레이션 엔진 완성 후로 미룸

## 13. 데이터/거래 API 조합

| 용도 | API | 비고 |
|---|---|---|
| 거래 실행 + 시세조회 (메인) | **토스증권 오픈API** | 2026.08 정식출시, 국내+미국 통합, REST, OAuth2.0 |
| 밸류에이션/재무제표 | **DART 공시 API** | 무료, 공식 신뢰도 최고 등급 소스로도 활용 |
| 거시경제 변수 (금리/환율/CPI/GDP) | **한국은행 ECOS API** | 무료 |
| 한계 봉착 시 보완 | KIS API | 확장 옵션 |

- 종목 식별자가 API마다 다르므로 종목 매핑 테이블 필요
- **기능별 API 사용범위**:
  - ① 직접모의투자, ② AI모의투자: 시세/계좌 조회 API만 사용, 실제 주문 API는 호출하지 않음 (내부 가상체결 로직으로 시뮬레이션)
  - ③ AI실전투자: 실제 토스 주문 API 호출
- 아키텍처상 주문 실행부를 인터페이스로 분리해 `MockOrderExecutor`(모의용)와 `TossOrderExecutor`(실전용)를 갈아끼우는 구조로 설계
