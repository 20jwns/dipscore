# CLAUDE.md

이 파일은 이 저장소에서 작업하는 Claude Code에게 프로젝트 컨텍스트를 제공합니다.
전체 기획 상세는 `AI_모의투자_앱_최종기획서.md` 참고 (본 문서는 그 요약/작업지침).

## 프로젝트 개요

재테크 목적의 AI 모의투자 앱. **핵심 목표는 개발 경험이 아니라 실제 흑자를 낼 수 있는
투자 로직 구현**이다. 종목 데이터 + 투자 성향/전략을 결합한 "매수 매력도 지수"와
"저점 진입 스코어" 공식을 설계하고, 모의투자로 백테스트하며 공식을 계속 수정한다.
흑자 전환 후 공식이 안정화되면 실제 AI 투자(실전투자) 기능으로 확장한다.

자산군: 국내 주식, 미국 주식, ETF (코인 등 제외).

## 1차 개발 범위 (중요)

**직접 모의투자 + AI 모의투자 2개 기능만 먼저 개발한다. AI 실전투자는 이번 범위에서 제외.**

| 기능 | 설명 | 거래 API 사용 |
|---|---|---|
| ① 직접 모의투자 | 사용자가 직접 매매 판단, 가상 자산 시뮬레이션 | 시세/계좌 조회만 (주문 API 미사용) |
| ② AI 모의투자 | AI가 매수/매도 신호 생성, 가상 체결 시뮬레이션 | 시세/계좌 조회만 (주문 API 미사용) |
| ③ AI 실전투자 | AI 신호로 실제 계좌 매매 | ❌ 이번 범위 아님 — ①②가 백테스트+실운영으로 충분히 검증된 후 착수 |

- ①②는 실제 주문 API를 절대 호출하지 않는다. 내부 가상체결 로직으로만 시뮬레이션한다.
- ③ 착수 조건: AI 모의투자가 어느 정도 검증된 이후. 전환 후에도 최소 3개월 실운영 검증 기간 필요.
- 시뮬레이션 결과 화면(몬테카를로 히스토그램/스파게티차트 등)은 2차 개발로, 시뮬레이션 엔진 완성 후 진행.

## 핵심 화면 우선순위

**1차 개발 (직접모의투자+AI모의투자에 필요한 화면만)**
1. 홈 — 요약카드(총손익/오늘신호/보유종목) + 오늘의 신호 리스트 + 보유종목 요약
2. 종목 스코어 랭킹 — 섹터/자산군 필터 + 정렬 + 리스트
3. 종목 상세(간이) — 캔들차트 + 저점진입스코어 breakdown + 매력도지수 breakdown
4. 매매 알림 — 푸시+인앱, 딥링크 연결
5. 전략 설정 — 온보딩 설문(5~7문항) + 핵심 슬라이더(리스크허용도/종목당최대비중/투자스타일) + 상세설정(접힘)

**2차 개발**
- 시뮬레이션 결과 — 요약박스 + 히스토그램 + 스파게티차트 + 국면별탭 + 벤치마크 비교 오버레이

**3차 (추후, 재우선순위화 대상)**
- 고도화 알림, 대시보드 커스터마이징

**개발 워크플로우**: 화면별 PNG 시안 → 구현 → 체크포인트 (Triplan 프로젝트와 동일 방식).

## 핵심 공식

### 매력도 지수 (Attractiveness Score)

```
매력도 지수 = 기본점수(펀더멘털+수급+거시) × 이벤트 조정계수
```

- **기본점수**: 밸류에이션/재무건전성/수익성·성장성/사업경쟁력/수급(종목 펀더멘털) +
  거시경제/산업사이클/시장심리/글로벌연동(거시·기술적 변수)
  - 정규화: 밸류에이션·재무·수익성 등은 **업종 percentile**, 거시경제 변수는 **Z-score**,
    ETF는 기초자산 카테고리별 별도 percentile 그룹
  - 가중치 산정 4단계: 전문가초안 → 베이지안 최적화 → walk-forward validation → 요인 제거 테스트
    (1차는 핵심 요인 5~7개로 시작, 분기/반기 재검증)
- **이벤트 조정계수**: `카테고리별 기본조정폭 × 감성점수 강도` (카테고리 상한선으로 안전장치)
  - 감성분석은 직접 파인튜닝, 부정 이벤트 우선 반영(리스크 관리 우선)
  - 출처 신뢰도 가중: 공식공시/1보(0.7 이상) > 후속보도(낮음) > 커뮤니티/SNS(완전 배제)
  - 감쇠: 단발성(5~7일) / 진행형 리스크(느린 감쇠) / 정책·구조적(감쇠 없음, 갱신시까지 유지)

### 저점 진입 스코어 (Entry Score)

```
저점 진입 스코어 = (반등신호 × 가중치A) + (기술적지표 × 가중치B) + (매력도지수 × 가중치C)
```

- **반등신호**: ATR 대비 상대 구간 정규화 (0.5~1.5×ATR 구간 최고점)
- **기술적지표**: RSI(14일, 과매도 30 이하 후 상향돌파) + 볼린저밴드(20일 하단선 터치 후 복귀)
- **매력도지수**: 1차 필터(기본점수 ≥60 통과 종목만) + 2차 가중요소(C) 이중 역할
- 가중치 초안: A(반등신호) 0.3 / B(기술지표) 0.3 / C(매력도지수) 0.4 — 매력도지수와 동일한
  4단계 방법론으로 확정. 진입조건 임계값(스코어 ≥70)도 백테스트로 조정

### 매매 신호 룰

```
매수: 저점진입스코어≥70 AND 기본점수≥60 AND 이벤트조정계수≥0.9(음수이벤트 없음) AND 보유현금>최소매수단위
매도: 목표수익률 도달(+2~3%) OR 손절률 도달(ATR×1~1.5배) OR 보유시간 초과(15:20 강제청산)
```

## 작업 시 유의사항

- 공식의 세부 수치(카테고리별 조정폭, 콜드스타트 전략 등)는 미확정 상태로, 백테스트 결과에 따라
  계속 바뀔 예정 — 하드코딩보다 설정값으로 분리해 튜닝 용이하게 구현할 것.
- 백테스트는 생존편향 방지(Point-in-Time 유니버스), 거래비용 반영, train/validation/test
  3-way 분할(test는 마지막 1회만), walk-forward validation 원칙을 지킬 것.
- 미국주식 양도소득세 export, 홈택스 신고 알림 등 세금 관리 기능은 확정 요구사항이니 후순위로 미루지 말 것.
- **`backend/.env` 값을 바꾼 뒤 반영 안 되면**: (1) 서버를 완전히 재시작해야 함(핫리로드 안 됨, 죽었는지
  `lsof -ti:8080` 로 실제 확인할 것) (2) `./gradlew bootRun` 은 반드시 `backend/` 안에서 실행(spring-dotenv 가
  cwd 기준으로 `.env` 탐색) (3) `.env` 키 이름은 `application.yml` 의 `${...}` placeholder 안 이름과
  정확히 일치해야 함 — `.env` 는 진짜 OS 환경변수가 아니라 spring-dotenv 를 거치므로 Spring 의 relaxed
  binding(전체 경로 이름 자동 변환)이 적용 안 됨. 자세한 진단 방법은 `backend/README.md` 의 해당 트러블슈팅
  절 참고.
